What is the Event Loop?
- The Event Loop is the mechanism that allows Node.js to perform non-blocking (asynchronous) operations.
- It continuously checks whether the Call Stack is empty. If it is empty, it takes the next callback from the Callback Queue and executes it.

- Definition (Exam/Interview):
The Event Loop is a process that continuously monitors the Call Stack and, whenever it becomes empty, moves the next callback from the Callback Queue to the Call Stack for execution.

- Why Do We Need the Event Loop?
Node.js runs JavaScript on a single thread.
If Node.js waited for every slow task (like reading a file or fetching data from a database), the entire application would stop until that task finished.
Instead, Node.js sends these slow tasks to the background and continues executing the remaining code. Once the task is complete, its callback is executed using the Event Loop.
This makes Node.js fast and efficient.

- Real-Life Analogy 
Imagine a restaurant.
Customer Places an order.
Waiter (Node.js Main Thread) Takes the order but does not cook the food.
Chef (OS/libuv) Prepares the food in the background.
Manager (Event Loop) Checks whether the waiter is free. If the waiter is free, the manager tells the waiter to serve the prepared food.

Mapping
Restaurant	Node.js
Waiter	Main Thread
Chef	OS/libuv
Manager	Event Loop
Ready Food	Callback Queue


Components of the Event Loop

1. Call Stack
The Call Stack is where JavaScript executes code.

- Executes one task at a time.
- Follows the LIFO (Last In, First Out) principle.
- When a function finishes, it is removed from the stack.
Example: console.log("Hello");
Execution: Call Stack
------------
console.log()
------------
After execution: Call Stack (empty)

2. OS / libuv
Some operations take time.
Examples:
- setTimeout()
- setInterval()
- fs.readFile()
- Database queries
- API requests
- Network operations
Instead of waiting, Node.js sends these tasks to libuv, which uses the operating system to handle them in the background.
